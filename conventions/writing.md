# 개조식 작성 규약

**정본.** `install.sh` 가 각 repo(infra 자신·워크스페이스 루트 포함)의 `.claude/rules/writing-style.md` 로 설치하고, `/commit`·`/pr`·`/issue` 스킬이 본문을 쓰기 전에 읽는다.

## 적용 범위

- 적용: commit·PR·issue 의 제목, commit 본문, PR 본문(STAR 전 섹션), issue 본문의 모델 작성부(왜·무엇을)
- 제외: 코드 블록, 표의 셀, 사용자가 직접 쓴 문장의 인용
- 언어: 한국어, 기술 용어·식별자는 영어

## 원칙

1. **문장 없음.** 모든 줄은 불릿. 종결은 명사구.
   - 금지 종결: `다` 로 끝나는 서술형 전부(`~하다` `~한다` `~했다` `~이다`), `~함` `~됨` `~임`
   - 상태 어휘: `초과` `미만` `동일` `보류` `삭제` `소멸` `해소`
   - 부정은 `없음`·수치로: `알림 없음` `라벨 없음` `수정 대상 0건`. `미`·`무` 접두사(`미부여` `무알림`) 금지
   - 조사로 끝나지 않음. `A 를 B 로` 는 동사가 빠져 뜻이 갈림(`분해로` 가 방법인지 대상인지). `A 를 B 로 교체` 처럼 명사 동작으로 닫음
2. **접속사 없음.** 관계는 뎁스와 라벨로만 표현.
   - 부연·구성 요소·상세: 라벨 없이 아래 뎁스
   - 종속 이외의 관계: 아래 라벨 목록의 라벨을 앞머리에. 목록은 닫힌 집합
3. **뎁스 상한 5.** `##` 섹션은 세지 않고 그 아래 첫 층(`###` 또는 최상위 불릿)이 1. 불릿 4단(GitHub 의 ■ 마커)은 상위 재구성 검토
4. **한 불릿 한 정보.** 쉼표로 두 정보를 잇지 않음. 분해는 형제 불릿, 뎁스 아님. 동종 항목의 열거는 가운뎃점(`·`)으로 한 불릿 허용
5. **순서는 번호 목록.** 불릿은 순서 무관, 절차·시도 순서는 `1.` `2.`
6. **표는 유지.** 대조·비교·매핑 정보는 기존 규칙대로 표

## 제목

세 매체가 한 모양. `대상 + 동작명사` 한 덩어리로 닫는다.

- 종결은 동작명사 하나: 추가·제거·분리·전환·통합·정리·이관·강제·허용·결정·은퇴·갱신
- 동작은 하나. 두 동작을 `하고`로 잇지 않음. 상위 동작 하나로 올리거나 이슈 분리
- 수단·범위는 조사로 앞에: `SSE 양방향 하트비트로 죽은 연결 서버 측 정리`
- 괄호 부연은 단계 표기만: `(2단계)`. 날짜·출처·`vs` 는 본문
- PR 제목은 연관 이슈 제목과 동일. 이슈 없을 때만 새로 작성
- prefix 는 commit 만(`docs: `). PR·issue 는 없음
- 길이 40자 이내 권장, 70자 상한

| 현재 | 규약 적용 |
|---|---|
| `item_snapshots.edited_by 컬럼을 제거한다` | `item_snapshots.edited_by 컬럼 제거` |
| `SSE 결측 정리 스위치를 없애고 항상 켠다` | `SSE 결측 정리 스위치 제거` |
| `초대 프리뷰의 게스트 토큰 발급 시점 - 자동 발급 유지 vs 참여 시점 발급` | `초대 프리뷰 게스트 토큰 발급 시점 결정` |
| `run_container.sh 사용 예의 컨테이너 이름을 현행으로` | `run_container.sh 사용 예 컨테이너 이름 갱신` |
| `refactor: 파싱 요청 테이블 추가와 적재 기록 (#1073 A)` | `파싱 요청 테이블 분리 (1단계)` |

## 구조

매체가 갈린다. PR·issue 는 마크다운 렌더링, commit 은 평문(`#` 줄은 커밋 시 주석으로 제거, `**` 는 그대로 노출).

| 매체 | 첫 층 | 그 아래 | 라벨 |
|---|---|---|---|
| PR·issue | `##` 섹션 아래 항목마다 `###` | 불릿 | 굵게 |
| commit | 최상위 불릿 | 불릿 | 평문 |

- `###` 은 항목 하나. 아래 불릿 0개 허용
- `###` 제목도 명사구. 라벨이 항목 자체면 제목이 라벨(`### 후속`)
- 항목이 여럿이라도 `###` 없이 불릿만 두지 않음. 섹션 안 구조를 한 가지로

## 라벨 목록

형식은 `라벨: 내용`, 콜론 뒤 공백 1. 이유는 `원인` 하나, 사실은 `결과` 하나. 같은 뜻의 라벨을 둘 두지 않음. PR·issue 에서는 라벨을 굵게(`**원인:** 내용`), commit 에서는 평문. 굵지 않은 앞머리 콜론은 라벨이 아니므로 PR·issue 에서 라벨 밖 앞머리 콜론 금지. 목록 밖 라벨 금지. 같은 뜻의 변형(`이유` `왜` `배경` `사유` `근거` `실측`) 금지.

| 라벨 | 뜻 |
|---|---|
| `원인` | 이유. 현상의 원인과 결정의 근거 모두 |
| `결과` | 상위로 생긴 사실. 수치 포함 |
| `대안` | 검토했으나 채택하지 않은 선택지. 출처가 정보면 괄호: `대안: (리뷰 제안) ...` |
| `기각` | 대안을 버린 이유. 가정적 결과("X 였다면 Y 장애")도 여기 |
| `비용` | 채택한 쪽이 지불하는 대가 |
| `조건` | 상위가 성립하는 전제 |
| `예외` | 상위가 적용되지 않는 경우 |
| `이전` | 변경 전 상태. 구간이 정보면 괄호: `이전: (#1053 부터) ...` |
| `범위` | 이슈·계획과 달라진 범위. 부분 구현·초과·제외 |
| `위험` | 남는 리스크 |
| `후속` | 뒤따를 작업 |
| `참조` | 링크·정본 위치 |
| `구현` | 코드 식별자 묶음. PR Action 한 곳 |

- `기각` 은 `대안` 아래에만
- `대안` 아래 `결과` 는 그 대안의 실험값
- `해소`와 `소멸`의 구분: 해소는 문제가 풀린 것, 소멸은 대상이 없어진 것

## 예시

commit 본문:

```text
refactor: DB schema squash 와 테이블명 복수형 통일

- 마이그레이션 2개 추가: drop_legacy_tables · create_init_schema
  - 대안: V1-V18 전체 삭제 squash
    - 기각: 운영 RDS 자동 마이그레이션 흐름 보존 필요
- tournament_histories.tournament_id 인덱스 추가
  - 원인: 풀스캔
```

PR Result:

```markdown
## Result

### 동시성 1 로 회귀
- **원인:** CPU 병목
  - **결과:** N=2 부터 처리량 이득 0
  - **결과:** p95 20s 초과
- **대안:** 브라우저 컨텍스트 재사용
  - **결과:** 렌더당 메모리 40%·시간 20% 절감
  - **기각:** 처리량 무관

### 후속
- prod 배포는 workflow_dispatch 수동
```

같은 내용의 금지 형태:

```markdown
- CPU 가 병목이라 N=2 부터 처리량 이득이 없었고, 컨텍스트 재사용도 검토했으나 처리량과 무관해서 동시성을 1 로 회귀함
```

## 검토 질문

- 불릿 안에 `그래서` `하지만` `때문에` `및` 이 있는가: 뎁스나 라벨로 분해
- 어미가 `다` `함` `됨` 으로 끝나는가: 명사구로 교체
- 라벨이 목록 밖인가: 목록 안 라벨로 교체 또는 라벨 제거
- 조사(`로` `에` `와`)로 끝나는가: 명사 동작으로 닫기
- PR·issue 에 굵지 않은 앞머리 콜론이 있는가: 상위 항목과 아래 불릿으로 분해
- PR·issue 의 `##` 아래가 `###` 없이 불릿으로 시작하는가: 항목을 `###` 으로 승격
- 불릿 4단이 있는가: 상위 재구성 검토. 총 뎁스 5 초과는 금지
- 제목이 동작명사 하나로 끝나는가: `다`·조사·`하고` 연결은 재작성
