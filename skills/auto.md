하네스·문서 작업을 이슈 생성부터 PR 까지 멈춤 없이 진행한다. 머지만 승인을 기다린다.

**PR 까지는 무인, 머지는 승인 대기. 지시에 "머지까지" 가 있으면 그 문턱도 없다.**

## 언제 쓰나

- 스킬·훅·규약·문서처럼 절차가 정해진 작업을 맡길 때. 백로그를 통째로 넘겨도 된다.
- 사용자가 자리를 비우는 동안 진행시킬 때. 매 단계 확인을 받지 않는 대신 마지막에 한 번 보고한다.

## 적용 범위 (하드 가드)

**허용**: 스킬(`skills/`), 훅(`hooks/`, `claude/`), 규약(`conventions/`, `.claude/rules`), 리포 설정, README·문서, 워크플로(`.github/`).

**거부**: 서비스 코드(`src/` 앱 코드), DB 마이그레이션, 배포·인프라 실행(terraform apply, workflow_dispatch), 계약 카탈로그(`contracts/`).

거부 대상이면 착수하지 않고 "일반 흐름(사람 확인 동반)으로 진행하라" 고 안내한다. 판단이 애매하면 물어본다. 애매한 것을 자기 판단으로 허용 쪽에 붙이지 않는다.

## 루프 (작업 항목 하나당)

1. **worktree 분기**: 이슈를 먼저 만들어 번호를 확보하고, 최신 origin base 를 fetch 한 뒤 `<repo>/.claude/worktrees/<slug>` 에 `<prefix>/<이슈번호>-<slug>` 브랜치로 분기한다.
2. **구현**: 서브에이전트에 위임해도 된다.
3. **실측 검증**: 에이전트 보고도 자기 완료 선언도 증거가 아니다. 변경 종류에 맞는 독립 실행으로 확인한다 (셸이면 `bash -n`·shellcheck, 설치 스크립트면 임시 HOME 스모크, 문서면 금지문자 grep). 실패는 숨기지 않고 그대로 보고한다.
4. **커밋·push**: commit-msg 훅 형식(`<type>: <제목>`)을 지킨다.
5. **PR 생성**: `/pr` 스킬의 create 모드 절차를 따른다. 무인이라 본문 확인 게이트는 건너뛰되 assignee·라벨·Project 등록·`close #<이슈>` 는 그대로 채운다.
6. **CI 확인**: green 을 확인한다. `BEHIND` 면 `gh pr update-branch` 후 재확인한다.
7. **멈춤**: 기본은 여기서 멈추고 PR 링크·diff 요약·검증 결과를 보고한 뒤 머지 승인을 기다린다. 지시에 "머지까지" 가 있었으면 squash 머지(제목 `<type>: <PR 제목> (#N)`) 후 worktree·로컬 브랜치·임시파일까지 정리한다.
8. **다음 항목**: 백로그가 여러 개면 하나를 끝내고(머지 대기면 보고까지) 다음으로 넘어간다.

## 품질 규칙

- **단일 주제 diff**: 한 PR 은 한 주제만. 주제가 섞이면 항목을 쪼개 PR 을 나눈다.
- **주석은 한 줄**: 숙련 개발자가 그 주석 없이 놓칠 정보만 남긴다. 블록 에세이 금지.
- **금지 문자**: em dash, 물결, 이모지. 문서·코드·커밋·PR 본문 전부 해당.
- **PR 본문은 STAR 짧게**: 결정과 이유가 본론이고 diff 나열은 최소.
